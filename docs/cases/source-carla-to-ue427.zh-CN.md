# Source CARLA → UE4.27 迁移案例

将一个自定义道路场景迁入独立 UE4.27 项目，修复天空和材质问题，并通过性能对比撤回一次无效的 LOD 调整。本页展示实际处理记录，不提供地图下载。

## 背景与结果

- **路线**：Source CARLA → vanilla UE4.27.2；目标是独立项目中的 Content 交付。
- **迁移结果**：干净项目结构检查记录了 605 个资源，其中 241 个静态网格资源；未发现缺失内部依赖、外部项目依赖或无法加载的资源。
- **修复结果**：完成晴天与材质修复，后续记录包含重新打开、PIE、道路碰撞和固定视角视觉检查。
- **优化结果**：LOD 候选没有产生有效的整体收益，已回滚。

## 迁移步骤

1. **建立基线**：保留源项目和中间副本，记录资源清单、依赖与哈希。
2. **迁移内容**：使用编辑器的 Migrate，经过中间项目把地图及依赖迁入目标项目。
3. **处理目标差异**：在 UE4.27 中处理环境、材质和引用，保存后重新检查。
4. **验证独立交付**：再迁入干净 UE4.27 项目，核对依赖并重新打开、运行；后续修复另做验证。

Codex 按路线组织检查与计划，主机脚本核对包、清单和指标；Migrate、资产属性修改、保存和 PIE 由 Unreal 上下文执行，不是一条 CLI 命令自动完成。

## LOD 实验与回滚

在功能基线通过后尝试 LOD 调整，使用一致条件采样：

| 指标 | 基线 | LOD 候选 |
|---|---:|---:|
| 平均 FPS | 113.40 | 112.81 |
| 平均帧时间 | 8.818 ms | 8.864 ms |
| P95 帧时间 | 8.729 ms | 8.713 ms |

候选的绘制 primitive 数减少约 76.79%，但 Draw calls 增加约 16.22%；平均帧时间没有改善，P95 改善也仅约 0.18%。

**结论：回滚 LOD 候选。** 收益未达到预设的 3% 有效收益门槛。记录确认已回滚并重新验证，也未继续实施更高风险的阴影或绘制距离调整。

测试条件：i5-14400F、RTX 4060 Ti 8 GB、Ubuntu 22.04.5、UE4.27.2；640×372、Low、VSync 关闭、无 FPS 上限。五个固定视角，每视角三次，每次采样 300 帧，前后各 4,500 帧，预热 240 帧；协议记录相机、交通和传感器配置一致。

上方视觉截图为 1600×900，不是性能采样画质；这组较早的 LOD 实验也不代表后续晴天状态的性能。
