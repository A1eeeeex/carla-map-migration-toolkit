## Local Goal completion versus actual publication

The local preparation Goal covers the installable source candidate, truthful
capability/evidence documentation, scoped privacy checks and rollback snapshot.
It does not confer the stricter RC label or permission to publish. The source
archive uses one repository-root folder and includes no installation cache,
virtual environment or private development data. Verify its SHA256SUMS and
use that folder for the documented local marketplace installation.

At publication time, choose the release label, confirm the intended commit
matches the tested source manifest, complete the existing repository's Actions
check and private-reporting setup, then obtain explicit push/visibility/Release
authorization. Keep the three-route strict RC gate below open until its actual
evidence exists; do not turn it into an automatic full-test rerun for doc edits.

Eight cited small evidence files still match their recorded hashes. This
reuses the existing Source runtime and UE4.27 delivery records; it does not
rerun or upgrade their validation levels. The 435-test baseline is reused only
for unchanged production code. Later documentation-only edits receive text
checks and refreshed hashes, not another engine or full-suite run.

Two intermediate closeout failures were resolved: an installation-document
test still expected the old CLI version, and a demo invocation used a forbidden
in-repository output directory. The corrected assertion passed in the 22-test
run; the demo passed in a separate empty temporary directory. The latter was
an invocation error caught by the existing safety guard, not a product change.

## Proportional verification

Reuse the full host baseline while production code is unchanged. Run the
installation, Plugin structure, publication and demo checks once on the final
snapshot. Re-evaluate changed descriptions and known failures, not the entire
old matrix on every edit. Check cited small records, not engine binaries or
whole map trees. Documentation changes do not require an engine launch.

After freezing the manifest, documentation-only edits need link/text checks
and refreshed hashes; script changes need their targeted tests. After an
authorized commit, byte identity to the tested candidate can preserve evidence
without another full test run.
