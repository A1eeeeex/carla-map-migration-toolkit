# 这个工具包现在能做什么？

它是让 Codex 按可靠流程处理地图的 **三条路线 Skill + 共享脚本**。
不是一个点击后自动完成所有导入、修复和优化的软件，也不附带地图或引擎。

## 能力清单

| 你要做的事 | 工具包能提供什么 | 执行方式 |
|---|---|---|
| 把 RoadRunner 地图导入 Source CARLA | 区分 Datasmith / FBX 导入路线，检查文件、版本、Dataprep 提交与保存，指导后续验证 | 自动检查 + 编辑器操作指引 |
| 把 Source 地图交给发行版 CARLA | 检查 Package JSON、MapsToCook、Cook 依赖和平台匹配，指导构建、安装和独立运行验证 | 计划/审计脚本 + 实际构建与运行 |
| 把 CARLA 地图变成原版 UE4.27 地图 | 分类 CARLA/插件依赖，规划类替换、材质/引用/世界设置修复，要求第二干净项目验收 | 计划/证据脚本 + Unreal API/编辑器操作 |
| 做固定格式的 Content-only 交付 | 保持约定的资源路径和大小写，指导生产端打包、接收端复制，检查双层 Content 和混入的工程/缓存文件 | 自动审计 + 交付操作指引 |
| 检查地图压缩包是否安全、完整 | tar/zip/目录审计，检查路径穿越、链接、特殊文件、重复路径、展开大小，以及指定地图/XODR/可选 Cook sidecar | 自动只读脚本 |
| 生成交付文件清单 | 检查指定地图确实存在，逐文件记录路径、字节数、SHA256、地图路径和 UE4.27 版本 | 自动脚本；不覆盖现有报告 |
| 排查黑材质、空地图、碰撞和晴天显示问题 | 按保存状态、资源路径、父材质/贴图、虚拟纹理、类依赖、光照/曝光、版本和哈希逐项定位 | 操作与故障指引；不承诺自动修复所有情况 |
| 分析并优化地图性能 | 制定固定移动路线采样；定位线程、GPU、阴影、绘制调用、几何/显存瓶颈；分阶段评估 LOD、实例化、裁剪等候选方案 | 分析/优化指引；高风险改动须审查 |
| 看清性能优化是否有得有失 | 比较 mean/median/p95/p99/max，逐项列出改善、退化、缺失和无效数据；严格验收另查测试条件和保护项哈希 | 自动数据比较 |
| 安全推进、记录结果并回滚 | 限定允许路径、生成带哈希计划、检查执行上下文、保存备份/回滚元数据、绑定阶段证据，区分 PASS 与 NOT_RUN | 共享安全和证据能力 |

修复、交付和性能优化都属于三条路线内部，不需要再安装第四个“性能 Skill”。
已经迁移到 UE4.27 的 CARLA 地图可以从交付阶段继续，不必为了审计重走导入。

## 这轮具体补了什么

- 新增 `map-package-audit`：按指定地图检查 CARLA 包，而不只是搜任意 `.umap`。
- 新增 `content-audit`：检查 Content-only 交付格式、资源根和压缩包安全。
- 新增 `delivery-manifest`：生成确定性文件哈希清单，拒绝不存在的地图和链接文件。
- 新增 `compare-metrics`：直接读取已有性能汇总，列出每项得失，不用重启引擎。
- 改进 `compare-performance`：主指标变好时，也不再隐藏其他计数器的退化。
- 补齐生产端/接收端交付、黑材质/晴天、Cook 遗漏、移动路线采样和分阶段优化指引。

上述命令在 `host-cpython` 执行。前三项仅读取地图/压缩包；指定 `--output`
才写新的报告。四项新增命令可重复传入 `--allowed-root`，分别允许输入和
报告目录；不需要授权整个 home 或挂载根目录。

## 明确的边界

包结构正确 ≠ 地图在 Unreal 中正常打开；哈希相同 ≠ cold-copy 验收通过；
某个 GPU 指标降低 ≠ 整体性能一定提高。因此新审计报告不代替真实编辑器、
运行时或第二项目测试，也不会自动升级既有路线的兼容性声明。

优化默认保护 LOD0、材质槽、变换、道路几何、XODR、可驾驶碰撞和语义对象。
不会为跑分擅自删除交通设施、碰撞或路面。测试优先复用已有有效记录；
只重测修改影响的部分，再对最终候选做一次必要的综合验收。显存不足先等待。

不覆盖 UE5 降级、通用 Unreal 游戏优化、Apollo 控制器或 OpenDRIVE 编辑器。
当前真实兼容性/发布状态仍以[状态页](current-status.md)和路线证据为准；
“有操作指南”“脚本测试通过”不等于所有地图、所有版本均已实测支持。
